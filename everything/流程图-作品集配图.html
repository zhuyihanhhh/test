只读 Action · 读取界面状态与已加载镜头
· 准备确定性配置上下文
· 校验组装方案 / 提交正则
Agent 可自由调用，不改变 Maya 状态
写入 Action（受约束） · 写入 Rig / 场景路径
· 应用配置草案、刷新指定行
· 填入提交表达式与目标绑定
路径只接受用户明确给出的值，
不允许 Agent 自行发现或编造
需人工确认 · 执行组装方案：confirmed=true
· 批量提交：永不自动触发
Agent 只填表达式与目标，
提交动作始终留给人点
校验先行 配置草案 / 提交正则 / 任务目标 URL 均先对当前作用域校验 —— 缺匹配或重复匹配直接拒绝，源配置永不被覆盖
异步执行 + 进度回传 长任务按变体回传进度；服务端 300 秒截断响应时保留会话并解锁面板，不误判为 DCC 执行失败

设计思路：Agent 负责理解意图、编排顺序与生成草案； 工具层负责「数据从哪来、什么能写、什么必须人确认」—— 把 AI 的不确定性关在校验与确认之外。

Maya 回调注册机制与病毒三道防线

配置驱动注册 + 执行前阻断 / 内存清理 / 落盘隔离　——　崩溃治理从「逐例排查」到「自动免疫」

二、打开文件时的病毒三道防线

1

执行前阻断　kBeforeOpen

关闭 script 节点自动执行开关 → 病毒代码在读场景阶段根本不会运行，而非执行后再补救

2

读取场景

恶意 script 节点以惰性数据形式进入场景，不触发执行

3

内存清理　kAfterOpen

双判据定位　名字黑名单（vaccine_gene / breed_gene / fuckVirus_gene / maya_secure_system …） ＋ 代码特征（import base64、write 等）
安全处理　跳过 reference 来源节点 → 解锁节点 → 删除
残留清理　按黑名单 kill 可疑 scriptJob；清理未知节点 / 未知插件 / 未知 DAG 节点
4

落盘隔离

扫描用户 Maya 脚本目录，非预期注入脚本改名隔离而非直接删除，保留回滚余地

5

恢复执行　kAfterOpen

还原 script 节点自动执行开关，正常功能节点不受影响

6

埋点上报

每次清理上报场景路径 + 被清节点清单，失败记告警 → 感染面与复发率可统计

工程取舍（白名单）：未知插件清理必须放过相机遮幅等关键插件 —— 抹掉 requires 条目后存盘，相机绑定里的遮幅会永久丢失且无任何提示，宁可留条目也不做静默破坏； 但白名单内的节点若检出危险代码，仍会被清掉。
同体系复用：保存前自动备份到时间戳目录、namespace 清理、reference 失败编辑清理、关键插件缺失兜底加载并暴露告警。
